# 感知仪表盘重新设计

设计稿：`index.html`、`preview.png`

## 目标

1. 先回答「此刻有什么可用」，再提供配置入口。
2. 健康感知独立成组，不再作为现实触及或模型能力的附属行。
3. 状态、来源、时效、待处理动作使用统一信息层级。
4. 仪表盘只读；所有配置动作通过明确的「去管理」入口跳转。

## 信息架构

- 页头：同步时间、通道计数、重新读取。
- 待处理条：只显示需要用户动作的项目，不把普通缺失当成错误。
- 第一行：
  - 此刻：时间、日期、农历、地点、天气、预警、附近纪念日。
  - 健康感知：绑定状态、数据范围、最近摘要、主动关心状态、绑定入口。
- 第二行：
  - 现实触及：定位、识屏、手机、摄像头、米家、授权记录。
  - 模型与连接：对话、语音、生图、视觉四条路由。
  - 主动与记录：主动联系用量、服务余额、外部资讯、撤回记录、健康主动事件。

## 视觉规则

- 健康用独立的心形/生命线图标，不再混入手机设备图标。
- 通道值统一为「状态短语 + 来源/时效」；不可用使用灰色，待授权使用琥珀色，可用使用绿色。
- 卡片底部固定为「边界说明 + 去管理」。
- 模型卡不使用四个大磁贴，改为紧凑路由列表，减少与健康、现实能力争夺视觉权重。

## 与现有实现映射

- `perceptionOverviewWorkspace`：整体替换为新的 dashboard 结构。
- 页头状态：复用现有 `/perception-native/runtime` 与原生感知快照。
- 健康卡：复用华为健康绑定状态、`health_enabled`、`health_proactive_enabled` 和最近摘要。
- 现实触及卡：复用现有 location / screen / phone / camera / mihome / authorization 数据。
- 模型卡：复用现有 model route 快照。
- 主动与记录卡：复用余额、新闻、撤回和主动联系摘要。
- 所有「去管理」入口复用现有 `config-health`、`config-screen`、`config-models`、`config-news` 深链接。

## 待确认

- 健康卡是否需要在仪表盘直接显示最近一次睡眠/运动摘要，还是只显示「已同步/未同步」。
- 现实触及未授权时，是保留整行状态，还是只收进顶部待处理条。
- 模型与连接是否需要在仪表盘显示 fallback 模型。
